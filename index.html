Network Traffic Analysis — C2 Beacon Detection

Problem Statement

A suspicious PCAP file was captured from an endpoint flagged by the EDR. The task was to identify whether the host was communicating with a Command & Control (C2) server, extract IOCs, and determine the malware family based on traffic patterns.

Approach

  • 01 Opened PCAP in Wireshark and applied display filters to isolate HTTP/HTTPS and DNS traffic
  • 02 Identified periodic beaconing at consistent 60-second intervals to a suspicious IP address
  • 03 Extracted DNS queries revealing domain generation algorithm (DGA) patterns
  • 04 Used VirusTotal and AbuseIPDB to confirm the C2 IP as malicious (Cobalt Strike beacon)
  • 05 Documented all IOCs: IPs, domains, JA3 hashes, and User-Agent strings

Tools Used

WiresharkNetworkMinerVirusTotalAbuseIPDBZeektshark

Key Lessons Learned

  • Beaconing traffic has predictable timing patterns detectable via statistical analysis
  • JA3/JA3S fingerprints are reliable indicators of specific malware families
  • DNS query volume spikes often indicate DGA-based C2 communication
  • Always correlate multiple data sources before attributing a threat

SIEM Alert Triage — Identifying True Positives in Elastic SIEM

Problem Statement

Given a pre-configured Elastic SIEM environment with 80+ triggered alerts from a simulated attack scenario (lateral movement + privilege escalation), the task was to triage alerts, separate true positives from false positives, and reconstruct the attack timeline.

Approach

  • 01 Prioritized alerts by severity (Critical > High > Medium) and grouped by host and user
  • 02 Correlated Sysmon Event IDs (1, 3, 7, 11, 13) to trace process execution chains
  • 03 Identified anomalous PowerShell execution with encoded commands — confirmed credential dumping attempt
  • 04 Mapped activity to MITRE ATT&CK: T1059.001 (PowerShell), T1003 (OS Credential Dumping), T1021 (Lateral Movement)
  • 05 Created a timeline report documenting the full attack chain from initial access to exfiltration attempt

Tools Used

Elastic SIEMSysmonKQLMITRE ATT&CK NavigatorSigma Rules

Key Lessons Learned

  • Alert correlation across multiple Event IDs is essential to reconstruct kill chains
  • Encoded PowerShell commands are a strong indicator of malicious intent and should auto-escalate
  • MITRE ATT&CK mapping accelerates triage by providing context for observed TTPs
  • SOC analysts must balance thoroughness with speed — prioritization frameworks are critical

OWASP Top 10 — Web Application Vulnerability Assessment

Problem Statement

A deliberately vulnerable web application (DVWA / Juice Shop) was provided. The objective was to identify and exploit OWASP Top 10 vulnerabilities — including SQL injection, broken authentication, and XSS — and produce a structured vulnerability report with remediation recommendations.

Approach

  • 01 Performed reconnaissance: directory enumeration and technology fingerprinting with Gobuster and Wappalyzer
  • 02 Intercepted and modified HTTP requests using Burp Suite to test input validation controls
  • 03 Exploited SQL injection on the login form to bypass authentication — extracted database schema with SQLmap
  • 04 Injected stored XSS payload via user profile field, demonstrating session hijacking risk
  • 05 Documented findings in a CVSS-scored vulnerability report with PoC and remediation steps

Tools Used

Burp SuiteSQLmapGobusterOWASP ZAPWappalyzerNikto

Key Lessons Learned

  • Parameterized queries and prepared statements completely eliminate SQL injection risk
  • Content Security Policy (CSP) headers are the primary defense against XSS attacks
  • Broken access control is the #1 OWASP risk — server-side authorization checks are non-negotiable
  • Structured vulnerability reporting with CVSS scoring is essential for risk prioritization

Static & Dynamic Malware Analysis — Suspicious PE Binary

Problem Statement

A suspicious Windows PE binary was submitted from an employee workstation after unusual outbound traffic was detected. The task was to perform both static and dynamic analysis to determine the malware's capabilities, persistence mechanisms, and network IOCs — without executing it on a live network.

Approach

  • 01 Calculated file hashes (MD5, SHA256) and submitted to VirusTotal — 34/72 engines flagged as trojan
  • 02 Static analysis with PEStudio: identified suspicious imports (VirtualAlloc, WriteProcessMemory), packed sections, and embedded strings
  • 03 Decompiled binary in Ghidra to identify obfuscated string decryption routine and C2 URL construction logic
  • 04 Executed in isolated FlareVM sandbox: monitored registry, file system, and network activity with Regshot and Process Monitor
  • 05 Confirmed persistence via Run key modification and identified C2 callback to hardcoded IP over port 4444

Tools Used

PEStudioGhidraVirusTotalProcess MonitorRegshotFlareVMWireshark

Key Lessons Learned

  • Static analysis alone is insufficient — dynamic execution reveals obfuscated behavior not visible in code
  • Registry Run keys and scheduled tasks are the most common Windows persistence mechanisms
  • Isolating the sandbox from the network is critical to prevent live C2 communication during analysis
  • String decryption routines in Ghidra can expose hardcoded IOCs that AV signatures may miss
